## 2. Пользовательские сценарии использования (дополненная версия)

### 2.1. Сценарий: Оператор контролирует параметры водной среды

**Актор:** Оператор предприятия

**Цель:** Убедиться в нормальном состоянии водной среды обитания аквакультуры

**Основной сценарий:**
1. Оператор открывает интерфейс системы на АРМ.
2. Видит графики и текущие значения по всем датчикам в двух точках контроля (вход и выход очистных).
3. В штатном режиме проверяет показания по регламенту.
4. **При выходе параметра из зелёной зоны получает уведомление.**
5. **При переходе параметра из жёлтой зоны в красную получает повторное уведомление.**
6. Анализирует ситуацию и при необходимости вызывает инженера или технолога.

### 2.2. Сценарий: Ответственный работник получает уведомление о критическом отклонении

**Актор:** Инженер / главный технолог (удалённый ответственный работник)

**Цель:** Оперативно отреагировать на недопустимое отклонение параметров

**Основной сценарий:**
1. Ответственный работник получает **индивидуальное уведомление** (по согласованному каналу: Telegram, email, SMS) о переходе параметра в красную зону.
2. Удалённо подключается к ЦОД предприятия через VPN с авторизацией.
3. Анализирует динамику изменений и исторические данные.
4. Принимает решение:
   - вызвать ремонтную бригаду;
   - проверить работу очистных сооружений;
   - скорректировать технологический процесс.
5. Фиксирует факт реагирования.

### 2.3. Сценарий: Аналитик-технолог исследует долгосрочные данные

**Актор:** Научный сотрудник (аналитик-технолог)

**Цель:** Выявить корреляции между параметрами водной среды и биологическими показателями

**Основной сценарий:**
1. Аналитик подключается к **удалённому серверу** через Интернет.
2. Запрашивает данные за несколько лет по одному или нескольким объектам.
3. Сравнивает динамику параметров (аммоний, нитраты, pH, кислород) с внешними данными (темпы роста, состав кормов).
4. Строит графики, выгружает данные для статистической обработки.
5. Использует результаты для научных отчётов или оптимизации технологии.

### 2.4. Сценарий: Администратор управляет доступом и резервным копированием

**Актор:** Администратор системы

**Цель:** Обеспечить безопасность, доступность и сохранность данных

**Основной сценарий:**
1. Администратор создаёт учётные записи новых пользователей.
2. Назначает роли: оператор, ответственный работник, аналитик-технолог.
3. Настраивает права доступа к ЦОД и удалённому серверу.
4. Контролирует активность пользователей и каналы VPN.
5. Организует регулярное резервное копирование данных ЦОД.
6. Обеспечивает асинхронную выгрузку данных на удалённый сервер.
