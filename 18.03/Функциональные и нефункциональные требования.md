# Функциональные и нефункциональные требования к системе автоматизированного химического контроля водной среды

## 1. Функциональные требования (FR)

### 1.1. Сбор и обработка данных с измерительного оборудования

| ID | Требование |
|----|------------|
| **FR-01** | Система должна обеспечивать интеграцию с измерительным комплексом **АТОН-801** (8 каналов), установленным в лаборатории ВИШ МИФИ. |
| **FR-02** | Система должна поддерживать сбор данных минимум по следующим параметрам: аммоний (NH₄⁺), нитраты (NO₃⁻), нитриты (NO₂⁻), pH, удельная электропроводность, ионы натрия (Na⁺), растворённый кислород (O₂), температура. |
| **FR-03** | Система должна получать данные от контроллеров прибора АТОН-801, которые выполняют первичный сбор, накопление и усреднение показаний. |
| **FR-04** | Система должна поддерживать настраиваемую периодичность опроса датчиков (дискретизацию) в диапазоне от 1 секунды до 1 часа (значение должно конфигурироваться администратором). |
| **FR-05** | Система должна обеспечивать **буферизацию данных** на промежуточном контроллере или самом приборе в случае потери связи с ЦОД, с последующей автоматической передачей накопленных данных при восстановлении соединения. |

### 1.2. Хранение данных (ЦОД предприятия)

| ID | Требование |
|----|------------|
| **FR-06** | Система должна обеспечивать приём данных от прибора АТОН-801 по локальной сети и запись их в **ЦОД предприятия**. |
| **FR-07** | Система должна хранить логи показаний в структурированном формате (реляционная БД или специализированная БД временных рядов) за период **не менее 1 года** с возможностью расширения. |
| **FR-08** | Система должна обеспечивать целостность и неизменность хранимых исторических данных. |
| **FR-09** | Система должна автоматически создавать **резервные копии** базы данных ЦОД по расписанию, настраиваемому администратором. |

### 1.3. Визуализация на АРМ оператора

| ID | Требование |
|----|------------|
| **FR-10** | Система должна предоставлять **веб-интерфейс** (или толстый клиент) для АРМ оператора с отображением текущих значений параметров в числовом виде. |
| **FR-11** | Система должна отображать графики (тренды) изменения каждого параметра за выбираемый пользователем интервал времени (час, сутки, неделя, месяц, год). |
| **FR-12** | Система должна визуально выделять **три зоны отклонений** для каждого параметра: зелёная (норма), жёлтая (значительные отклонения), красная (недопустимые отклонения). |
| **FR-13** | Интерфейс должен обеспечивать **приоритизацию событий**: при одновременном возникновении нескольких отклонений наиболее критичные (красная зона) отображаются выше жёлтых. |

### 1.4. Оповещение и уведомления

| ID | Требование |
|----|------------|
| **FR-14** | Система должна автоматически формировать уведомления при **выходе параметра из зелёной зоны** и при **переходе из жёлтой зоны в красную**. |
| **FR-15** | Уведомления должны отображаться на АРМ оператора в виде всплывающих окон и/или изменения цвета соответствующих индикаторов. |
| **FR-16** | Система должна поддерживать отправку **индивидуальных уведомлений ответственным лицам** (инженер, технолог) при переходе параметров в красную зону по следующим каналам: **Telegram, email, SMS** (состав каналов должен конфигурироваться для каждого получателя). |
| **FR-17** | Система должна требовать от оператора **подтверждения получения (acknowledgement)** уведомления о красной зоне. Факт подтверждения должен фиксироваться в логах. |
| **FR-18** | Система должна обеспечивать **повторную отправку уведомления** ответственному лицу, если доставка в первоначальном канале не удалась (например, нет соединения с Telegram). |
| **FR-19** | Система должна реализовывать **механизм эскалации**: если оператор не подтвердил получение красного уведомления в течение заданного времени (настраивается администратором, например, 5 минут), система автоматически отправляет уведомление вышестоящему ответственному лицу (главному инженеру, технологу). |
| **FR-20** | Система должна фиксировать в логах факты отправки, доставки и прочтения уведомлений (там, где это технически возможно). |

### 1.5. Удалённый доступ к ЦОД

| ID | Требование |
|----|------------|
| **FR-21** | Система должна обеспечивать **удалённый доступ к данным ЦОД** для авторизованных пользователей (ответственных работников) через сеть Интернет. |
| **FR-22** | Удалённый доступ должен осуществляться только по **защищённым VPN-каналам** с обязательной авторизацией (логин/пароль, возможно двухфакторная аутентификация). |
| **FR-23** | Удалённые пользователи должны иметь доступ к просмотру текущих параметров, графиков и исторических данных в объёме, соответствующем их роли. |

### 1.6. Передача данных на удалённый сервер (для аналитики)

| ID | Требование |
|----|------------|
| **FR-24** | Система должна обеспечивать **регулярную асинхронную выгрузку** накопленных данных из ЦОД предприятия на **удалённый сервер** (в научный институт). |
| **FR-25** | Периодичность выгрузки должна настраиваться администратором (например, ежедневно, еженедельно). |
| **FR-26** | На удалённом сервере данные должны храниться в структурированном виде в течение **неограниченного времени (многие годы)**. |
| **FR-27** | Система должна обеспечивать **доступ аналитиков-технологов** к данным на удалённом сервере через Интернет с разграничением прав (только чтение, возможность выгрузки). |

### 1.7. Администрирование и управление доступом

| ID | Требование |
|----|------------|
| **FR-28** | Система должна поддерживать **ролевую модель доступа** с как минимум четырьмя ролями: **Администратор**, **Оператор**, **Ответственный работник**, **Аналитик-технолог**. |
| **FR-29** | Администратор должен иметь возможность создавать, блокировать и удалять учётные записи пользователей, а также назначать им роли. |
| **FR-30** | Администратор должен иметь возможность настраивать **пороговые значения (зелёная/жёлтая/красная зоны)** для каждого параметра. Изменение порогов должно логироваться. |
| **FR-31** | Администратор должен иметь возможность настраивать параметры эскалации (время неответа оператора, цепочка эскалации). |
| **FR-32** | Система должна вести **журнал действий пользователей** (вход в систему, просмотр данных, подтверждение уведомлений, изменение настроек). |

## 2. Нефункциональные требования (NFR)

### 2.1. Требования к точности и производительности

| ID | Требование |
|----|------------|
| **NFR-01** | Погрешность измерений определяется метрологическими характеристиками прибора АТОН-801; система не должна вносить дополнительную погрешность при сборе и передаче данных. |
| **NFR-02** | Время задержки между изменением показаний датчика и отображением на АРМ оператора не должно превышать **2 секунд** (в штатном режиме работы сети). |
| **NFR-03** | Система должна обеспечивать возможность хранения и оперативного доступа к данным с частотой дискретизации **до 1 секунды** по каждому из 8 каналов. |
| **NFR-04** | Время загрузки графика за произвольный период (до 1 года) не должно превышать **5 секунд**. |

### 2.2. Требования к надёжности

| ID | Требование |
|----|------------|
| **NFR-05** | Система должна функционировать в круглосуточном режиме 24/7. |
| **NFR-06** | Коэффициент готовности (доступности) системы для оператора должен составлять не менее **99.5%** в годовом исчислении. |
| **NFR-07** | При потере сетевого соединения между прибором АТОН-801 и ЦОД, прибор или промежуточный контроллер должен сохранять данные в энергонезависимой памяти в течение **не менее 72 часов** и автоматически передавать их после восстановления связи. |
| **NFR-08** | Система должна сохранять работоспособность (возможность просмотра текущих данных с АРМ) при временных сбоях в каналах связи с удалённым сервером. |
| **NFR-09** | Восстановление работоспособности системы после сбоев электропитания должно происходить в автоматическом режиме без потери накопленных данных. |

### 2.3. Требования к безопасности

| ID | Требование |
|----|------------|
| **NFR-10** | Передача данных по открытым каналам связи (Интернет) должна осуществляться только через **защищённые VPN-туннели** (например, OpenVPN, IPSec). |
| **NFR-11** | Система должна поддерживать протокол **HTTPS** для всех веб-интерфейсов. |
| **NFR-12** | Пароли пользователей должны храниться в хешированном виде с использованием современных алгоритмов (например, bcrypt). |
| **NFR-13** | Должна быть реализована защита от автоматического подбора паролей (блокировка после N неудачных попыток). |
| **NFR-14** | Система должна обеспечивать разграничение доступа к данным на уровне ролей: аналитики не должны видеть служебную информацию, операторы не должны менять пороги и т.д. |

### 2.4. Требования к масштабированию и совместимости

| ID | Требование |
|----|------------|
| **NFR-15** | Архитектура системы должна допускать подключение **до 50 измерительных комплексов** АТОН-801 (или аналогичных) к одному ЦОД предприятия. |
| **NFR-16** | Система должна поддерживать экспорт данных в распространённые форматы (CSV, JSON, Excel) для последующего анализа сторонними инструментами. |
| **NFR-17** | API (при наличии) должен быть документирован и обеспечивать возможность интеграции с внешними информационными системами предприятия. |

### 2.5. Требования к эксплуатации и удобству использования

| ID | Требование |
|----|------------|
| **NFR-18** | Интерфейс оператора должен быть интуитивно понятным, не требующим длительного обучения (время освоения базовых функций — не более 1 часа). |
| **NFR-19** | Система должна обеспечивать отображение информации на экранах с разрешением не менее 1280x1024. |
| **NFR-20** | Цветовая индикация (зелёный/жёлтый/красный) должна быть различима пользователями с нарушением цветовосприятия (дальтониками) — дублирование формой или текстом. |
| **NFR-21** | Вся документация к системе (руководство оператора, администратора) должна быть предоставлена на русском языке. |

### 2.6. Требования к сопровождению и развитию

| ID | Требование |
|----|------------|
| **NFR-22** | Система должна поддерживать возможность удалённого обновления программного обеспечения (с соблюдением мер безопасности). |
| **NFR-23** | Код системы (или её конфигурация) должен быть документирован для возможности передачи другой команде разработки. |
